# Hand-off — NYX sibling protocol, Table 4 and Figure 12 (2026-08-29, later session)

Continues `Reproduce/HANDOFF.md`. Repo root `<repo>` (this checkout)
(A100 cluster, Slurm; a 4×A100 partition with a 2 h limit and one with an 8 h limit).
Python: the project conda environment.

## 1. Why this session happened

The NYX runs behind Table 4 and Figure 12 fed the model the **original** sibling
fields. A decoder only ever holds the **archived, lossily compressed** siblings, so
those numbers are not decoder-reproducible. Everything below is the correction, plus
four other defects found on the way.

## 2. Defects found and fixed

| # | Defect | Where | Effect |
|---|---|---|---|
| 1 | Siblings loaded from `<field>.f32` (originals) | `bench_compress_table.py` | NYX inflated by up to 8 dB |
| 2 | `bg_h` capped at 29 by `pick_bg_h_under_budget`'s default `h_candidates` | `base_script/bg_shard.py` default | Miranda's 240k budget spent only 54k (22 %) |
| 3 | DDP wall-clock budget charged rank-0's eval to the other ranks' training clock | `base_script/bg_stage.py` | 10 s budget gave 2.7 s of training; 4-GPU quality came out *below* 1-GPU |
| 4 | Reported PSNR was the last epoch, not the returned (best-weight) model | `bench_compress_table.py` | SPERR baryon off by 2.25 dB; looked like training hurt |
| 5 | NeurLZ built with MONAI's **default** features (1.98 M params) instead of NeurLZ's `(4,)*6` (3,415) | `SPERR/power_spectrum_fig12.py` | Baseline converged in 4 epochs instead of ~45; understated our advantage |

Fix 2 is applied locally in `bench_compress_table.py` (`H_CANDIDATES = range(3,128)`),
not in the shared `bg_shard.py`. Fix 3 edits shared code — **anything DDP + wall-clock
budget produced before it is void**.

## 5. Open problems — read before using any of the above

1. **Ours' time-to-1 % is not reproducible.** Same config, same seed: 6.03 s vs
   6.06 s on the crossing but 0.099 % vs 0.498 % on the final eps; across sibling
   modes the crossing jumps 4.25 / 9.56 / 11.33 s with no ordering that makes
   sense (enhanced should not be slowest). **Needs 3-seed medians before any of
   these numbers are reported.** Same for NeurLZ (14.3 → 18.3 s across repeats
   of one config, before the recipe fix).
2. **NeurLZ's schedule is periodic.** `CosineAnnealingLR(T_max=1500)` restarts
   three times inside 100 epochs (~5200 steps), and its max eps crosses 1 % back
   and forth: 2.86, 1.56, 1.31, 1.17, 0.93, 1.27, 1.09, 0.73, 1.20, 1.19. Reporting
   its first crossing invites "you picked a scheduler that bounces". `neurlz_ep100.py`
   ships an `anneal` variant (T_max = total steps) precisely to close that
   objection — **run both**.
3. **The single-GPU baseline samples 4 consecutive slices per update** while the
   4-GPU run draws one slice from each of four separated shards. On SPERR baryon
   the single-GPU curve oscillates and ends below its own peak (109.49 base →
   111.65 peak → 109.40 last) while the 4-GPU curve rises monotonically. Part of
   every 4-GPU quality margin is sampling coverage, not parallelism, and a single
   GPU could have it for free with random or strided sampling. Until that control
   is run, claim only that quality is not lost.
4. **Time-to-match is fragile where the quality gap is small.** SPERR temperature
   gives 1.32× only because the two peaks differ by 0.18 dB. It measures the gap,
   not the hardware.
5. **eps(k) is computed on the raw field**, per `Reproduce/HANDOFF.md`. The repo's
   `ours_lowk_trace.py` uses the overdensity instead. The raw-field base matches
   the draft's SZ3 curve (1.614 % at k=1), so raw looks right, but confirm before
   publishing.
6. **The draft's "3 s" for Ours does not hold on this hardware.** 3 s is 2 epochs
   here, and at 2 epochs k=1 is *worse* than the base (3.62 % against 1.61 %) —
   the model fixes k>=2 first. Ours needs ~5 epochs.
7. **`ours_lowk_trace.py` and `neurlz_ep100.py` still load original siblings.**
   Only `power_spectrum_fig12.py` was corrected.
8. Miranda's corrector: the 240k budget now yields 237,538 params, but the 4-GPU
   quality margin at that size is not reproducible (+1.38 dB one run, −1.26 dB the
   repeat). The 54k model is stable. Main table currently uses 54k.

## 6. Environment

4×A100 80 GB PCIe on the 4-GPU node, **no NVLink** — every pair is `SYS` (PCIe + cross-NUMA
UPI), which is why 4 GPUs give ~2× per step and not 4×. 2×AMD EPYC 9334, 1 TB RAM,
8 NUMA nodes. PyTorch 2.4.1+cu121, cuDNN 9.1.0, NCCL 2.20.5, bf16, TF32 off for
matmul / on for cuDNN.

Sibling archive: `SPERR/sperr_fft_cache/aux_streams/` (unpacked from
`handoff_aux_streams.tar.gz`). Levels 100–600 per field except temperature, which
stops at 500 — `available_levels()` scans what exists rather than assuming the grid.

Never overlap a Miranda-scale job with anything (1024³ peaks ~50 GB host RAM).
Write exports to shared storage, not `/tmp` — that is node-local and invisible from
the login node.

### Note (2026-09-12): the `aux_streams` archive vs. `git checkout`

`single-gpu` tracks `sec_4_evaluation/sperr_fft_cache/aux_streams` as a symlink to an
offloaded directory. On this branch that entry is removed and the real archive (65 `.bin`
streams, gitignored, + their `.json` metadata) lives at that path. Checking out `single-gpu`
in the same working tree replaces the directory with the symlink and **deletes the ignored
streams** (git treats ignored files as expendable). Keep the archive elsewhere and point
`ADAMIT_CACHE_DIR` at it if both branches are used in one checkout, or regenerate it with
`sec_4_evaluation/SPERR_fft.py --task aux_prep` (~25 min, CPU).
